METRIAL APPLICATION AUDIT AND REMEDIATION
2026-10-07 | Laravel 13.34.0 | PHP 8.5 | MySQL 8 / Redis 7

A. EXECUTIVE SUMMARY
The initial implementation had working location/RBAC foundations but incomplete authentication, OTP, profile, financial, category and notification workflows. The realtime service allowed unauthenticated arbitrary-room participation. Those surfaces have been implemented or corrected and exercised locally. The project remains a Laravel monolith.
Verdict: READY WITH CONDITIONS. This is not authorization to launch with disabled providers or development secrets. No known critical/high application defect remains from the inspected and tested paths; provider commissioning and production operational validation remain release gates. FCM/general email and addresses are not represented as implemented.
Verification labels: VERIFIED BY TEST = executed runtime evidence; VERIFIED BY STATIC CODE REVIEW = source/configuration inspection; NOT RUNTIME VERIFIED = external/deployment boundary. PASS means the specific local requirement passed within that boundary, not blanket production certification.
Scope: first-party application, migrations/seeders/factories, routes, configuration, translation catalogs, tests, Docker/Nginx/Socket.IO and dependency manifests. Dependency advisories were checked; third-party vendor source was not individually re-audited. No Git metadata was present, so no commit/history claim is made.

C. CRITICAL PROBLEMS FOUND
- Realtime accepted unauthenticated sockets, arbitrary rooms and client-controlled global events. Replaced by signed short-lived own-user credentials, explicit room authorization and server-only allowlisted relays. Seven Node tests passed, including real Redis delivery and cross-user rejection.
- Wallet, payment, verified webhooks and refunds were missing. Added durable SQL models, immutable ledger, integer money, locked transactions, idempotency keys/hashes, provider contracts and safe settlement/refund actions. MySQL concurrency tests prove the selected double-debit, duplicate-credit, replay and competing-refund cases.
- npm audit identified the shell-quote advisory GHSA-pqg4-j6r4-53mv through concurrently. Added a safe compatible dependency override and ran the tool smoke test. Both npm audits and Composer audit now report zero advisories in their current databases.

D. HIGH-PRIORITY PROBLEMS FOUND
- Missing admin/OTP login, logout, profile and verified phone changes now have explicit flows and tests.
- Role bypass is limited to active admins. Vendor approval cannot be bypassed by first changing a vendor to an intermediate status. Privileged status and role actions are audited.
- PATCH requests no longer overwrite omitted location fields. Nested translated writes cannot inject arbitrary columns. Route numeric constraints cover every nested parameter.
- Financial/identity retention uses restrictive FKs. Country deletion checks soft-deleted users. Seeding uses stable identifiers rather than mutable translated names.
- Production exceptions no longer expose SQL, provider bodies or stack traces through the API. Production error reporting keeps only safe class/location/request identifiers.

E. LOCALIZATION PROBLEMS FOUND
- Added complete Arabic/English validation and domain catalogs, including authentication, OTP, wallet, payments, categories and notifications.
- Corrected Arabic validation placeholder omissions and removed template-only validation entries. Attribution/license is preserved in THIRD_PARTY_NOTICES.txt.
- Locale handling resets per request, supports regional language normalization and applies to unmatched API errors. Queued notifications capture recipient locale instead of inheriting worker locale.
- Stable enum values, error codes, currency/ISO codes, route names and provider signatures remain untranslated. Technical exception internals are mapped to localized safe API errors.

F. ARCHITECTURE PROBLEMS FOUND
- Implemented thin controllers -> FormRequests -> focused Actions -> shared domain/provider services -> models -> Resources/jobs. Existing useful phone and audit contracts/DTOs were retained; no module architecture or meaningless repositories were added.
- Payment and SMS registries allow named configurations; Stripe and Twilio are the concrete shipped adapters. Additional brands require adapters and tests. SMS selects the default provider; automatic cross-provider retries are intentionally absent.
- Financial side effects are committed synchronously where consistency matters. Durable notification outbox publication is queued and recoverable by scheduler. After-commit domain events are extension points; delivery does not depend on an unregistered listener.
- Removed obsolete realtime demo/controller, duplicate JS configuration, unused controller and missing-package Scramble config; rewrote the stale README.

G. DATABASE PROBLEMS FOUND AND FINAL DATABASE REPORT
- users.phone has a global nullable unique constraint; soft-deleted phone identities remain reserved. phone_country_id is indexed and restricted by FK.
- Every country/governorate/city/category translation has UNIQUE(entity_id, locale) and an owning FK. Locale columns are indexed. Parent location/category deletion is RESTRICT; deleting a permitted parent entity cascades only its owned translations.
- Wallets are unique by (user_id, currency). Wallet transactions are unique by (wallet_id, idempotency_key); balances and amounts have DB checks. UPDATE/DELETE ledger triggers prevent mutation even through query-builder writes.
- Payments are unique by UUID, (user_id, idempotency_key), and (provider, provider_reference). Webhook events are unique by (provider, provider_event_id). Refunds are unique by UUID and (payment_id, idempotency_key). Request hashes reject conflicting reuse.
- Financial FKs restrict deletion of users, wallets, payments and refund actors. Ledger wallet/time, payment/refund status/time, category parent/active/sort, notification recipient/time and unpublished/time indexes support the implemented queries.
- OTP challenges use a unique scope and rotating challenge UUID. Notification event_key is unique, allowing retried business events to address the same durable notification.
- Fresh migrations and seeding succeeded on disposable SQLite and MySQL databases; the full seeder ran a second time on each. SeederIdentityTest checks translated-name changes and preserved activation state. Production-data upgrade/restore rehearsal remains pending.
- Supported target for production is MySQL 8; SQLite is used for fast tests. PostgreSQL/SQL Server migration compatibility is not claimed.

H. SECURITY PROBLEMS FOUND AND FINAL SECURITY REPORT

NOT RUNTIME VERIFIED: actual production secret provisioning, deployed debug mode/TLS/reverse proxy rules, backup permissions, history-level committed-secret absence, external penetration test. No Git repository was available. Existing .env was not printed or rewritten.
Issued socket credentials remain valid until expiry (120 seconds by default) after HTTP logout/blocking; clients are disconnected at expiry. Immediate global socket revocation is not implemented.

I. CONCURRENCY PROBLEMS FOUND
- OTP verification and its account mutation run under one locked SQL transaction; invalid attempt counts commit before the domain exception is returned. Simultaneous consumption yields one successful consumer.
- Wallet row locks plus conditional balance writes and unique operation keys prevent overdraft and duplicate mutation. First-wallet creation is serialized on the user.
- Payment/refund reservations serialize on payment rows; provider calls run outside the DB transaction and reuse stable UUID-derived provider keys. Webhook event insertion and ledger settlement commit together.
- Category tree mutations serialize on a database lock row to prevent simultaneous moves from creating cycles; maximum depth is five.
- Five separate-process MySQL tests passed: competing debits, identical idempotency keys, competing OTP consumers, repeated webhook settlement and competing refunds. These tests do not prove every possible interleaving under arbitrary outages.
