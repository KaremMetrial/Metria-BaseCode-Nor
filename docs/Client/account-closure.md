# Client — إغلاق الحساب واستعادة الوصول

[فهرس التوثيق](../README.md) · [عقد HTTP والأخطاء](../Shared/http-contract.md) · [كل المسارات](../ENDPOINTS.md)

الأمثلة توضيحية واقعية مطابقة لعقد التطبيق، وليست بيانات مستخدمين حقيقيين أو نتائج اتصال حي بمزود دفع. استبدل IDs والتوكنات والـOTP بالقيم الراجعة من بيئتك. الأمثلة تستخدم `X-Locale: en` لتثبيت لغة الرد.

## تسلسل الاستخدام

1. أعد التحقق من الهاتف خلال آخر خمس دقائق.
2. صفّر الأرصدة وسوِّ المدفوعات والاستردادات المعلقة قبل الإغلاق.
3. أرسل confirm=true، ثم امسح التوكن والبيانات المحلية وافصل Socket.

الإغلاق soft delete مع الاحتفاظ بالسجلات المالية. لا يوجد endpoint لإعادة الفتح تلقائيًا. من فقد هاتفه يتواصل مع الدعم؛ لا يُغيّر النموذج العام رقم الحساب ولا يثبت ملكيته.

| Method | Endpoint |

## أمثلة التدفق بالتفصيل

### 10.1 الإغلاق — DELETE /account

```sh
curl --fail-with-body -X DELETE "$CLIENT_BASE/account" \
  -H 'Accept: application/json' \
  -H 'X-Locale: en' \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"confirm":true}'
```

الاستجابة: **HTTP 200**.

```json
{
  "success": true,
  "message": null,
  "data": null
}
```

اعرض تأكيدًا واضحًا في الواجهة قبل الطلب. يحتاج تحققًا حديثًا؛ نفذ 6.1 و 6.2 إذا لزم. عند النجاح تُسحب كل الجلسات وPush وتُقفل المحافظ ويُغلق الحساب بالحذف الناعم. السجلات المالية والتدقيق تبقى محفوظة. الهاتف يظل محجوزًا ولا ينشئ حسابًا جديدًا بمجرد OTP. امسح بيانات التطبيق وافصل Socket.

إذا كان لأي محفظة رصيد غير صفر، أو توجد دفعة pending/processing، أو استرداد معلق، تكون الاستجابة **HTTP 409**:

```json
{
  "success": false,
  "code": "ACCOUNT_CLOSURE_BLOCKED",
  "message": "Resolve your wallet balance and pending payments or refunds before closing your account.",
  "errors": {}
}
```

اعرض سبب التعذر ووجّه المستخدم لتسوية الالتزامات أو الدعم؛ لا تكرر الطلب تلقائيًا.

### 10.2 فقدان الهاتف

اقرأ `data.recovery` من `/auth/requirements`. المسار الحالي `method: "support"` فقط. لا يوجد استرجاع ذاتي بالبريد أو endpoint لتجاوز ملكية الرقم أو لإعادة فتح حساب مغلق. عند فقدان الهاتف القديم استخدم رابط الدعم المهيأ؛ إذا كان null اعرض قناة الدعم التي يحددها المنتج بدل اختراع رابط. تدفق تغيير الهاتف العادي يحتاج الوصول للهاتف الحالي للتحقق الحديث.

## التعامل مع الفشل

401: أعد الدخول. 403: راجع نوع الحساب وحالته والصلاحيات. 404: لا تفترض ملكية المورد. 422: أصلح الحقول حسب errors. 429: احترم Retry-After إن وُجد. 500: احتفظ بـX-Request-ID. 503: راجع تهيئة الخدمات ولا تكرر عملية مالية بمفتاح جديد. تفاصيل 409 وسلوك إعادة المحاولة موضحة في تسلسل الميزة.
